02 · CoPL LOEO 실행 안내

run_copl_loeo.py의 구조, 스테이지, 명령, 산출물, 결과 공유 절차 · 2026-10-04

1. 코드 배치

run_copl_loeo.py                 드라이버 (CLI: --stage --data --timestamp --fast --set key=value)
reward/copl/loeo/
  config.py      Config dataclass + FAST 프리셋
  data.py        로더 재사용(reward/fully_bayesian/loeo/data.py), 채널 부분집합, population/적격 필터
  encoders.py    새 인코더 scatter / isobank / raw_rbf + 내재 지표(agree_cross, rho_cross, vote AUROC)
  graph.py       희소화 규칙 topk / mutual / epsilon / dense / cross_forced, 그래프 통계
  fold.py        한 폴드: prepare_fold(인코더+그래프+정규화) → train_models(GCF, RM) → evaluate_copl(예산·오프셋)
  baselines.py   PooledCNN(라벨마다 fine-tune), IndepCNN, KNNVote
  report.py      폴드 json 집계 (T-IV 집계 코드 재사용) + CoPL 전용 표·그림
reward/copl/dataset.py, gcf.py, trainer.py, rm.py   기존 모델 코드, 수정 없음
reward/copl/similarity/__init__.py                   레지스트리에 새 인코더 3개가 실행 시 등록됨

폴드마다 population 16명으로 인코더, 아이템 그래프, 채널 정규화, GCF, 보상 모형을 적합하고, held-out 스트림은 시간순 반분 뒤 예산 \(t\in\{0,5,10,20,n_{ctx}\}\), 오프셋 3개로 평가한다. 폴드 분할·예산·오프셋·지표 코드는 T-IV 드라이버와 같은 함수를 호출한다.

--stage all은 encoders, main, ablate, sweep, channels, adapt, report 순이다(tune 제외). 끝난 폴드 json은 건너뛰므로 중단 후 같은 --timestamp로 재개할 수 있고, report/ablate/sweep/channels/tune은 --timestamp를 생략하면 같은 run_name의 최신 폴더를 쓴다.

3. 권장 순서와 명령

모든 명령은 저장소 루트에서. .venv\Scripts\python.exe는 네 환경에 맞게. GPU가 있으면 자동으로 쓴다(device=auto).

3.1 인코더·채널 내재 지표 (먼저, GPU 없이도 가능)

.venv\Scripts\python.exe run_copl_loeo.py --stage encoders --set run_name=copl_loeo
.venv\Scripts\python.exe run_copl_loeo.py --stage report --set run_name=copl_loeo

기본은 enc_list=("ae","vae","pca","scatter","isobank","raw_rbf"), enc_channel_sets="loso"(전체 + 채널 하나 뺀 5개 + 단일 5개 + IMU). report/encoders.md의 k별 표에서 held-out vote MLPD와 agree_cross를 본다.

3.2 튜닝 (엄밀 모드: 폴드마다 내부 LOEO)

.venv\Scripts\python.exe run_copl_loeo.py --stage tune --set run_name=copl_loeo --set encoder=<3.1에서 고른 것>

폴드마다 folds/<name>_tune.json에 best가 저장된다. 이후 스테이지에 --set use_tuned=True를 주면 폴드별 best를 적용한다.

3.3 확정 실행

.venv\Scripts\python.exe run_copl_loeo.py --stage main --set run_name=copl_loeo --set encoder=<...> --set use_tuned=True --set seeds="(42,43,44)"
.venv\Scripts\python.exe run_copl_loeo.py --stage ablate   --set run_name=copl_loeo --set encoder=<...> --set use_tuned=True
.venv\Scripts\python.exe run_copl_loeo.py --stage sweep    --set run_name=copl_loeo --set encoder=<...> --set use_tuned=True
.venv\Scripts\python.exe run_copl_loeo.py --stage channels --set run_name=copl_loeo --set encoder=<...> --set use_tuned=True
.venv\Scripts\python.exe run_copl_loeo.py --stage report   --set run_name=copl_loeo

3.3b 다른 실행의 튜닝 결과 재사용, 적응 규칙 격자

.venv\Scripts\python.exe run_copl_loeo.py --stage adapt --set run_name=copl_loeo_adapt --set use_tuned=True --set tuned_from=outputs/copl_loeo_final/<timestamp>
.venv\Scripts\python.exe run_copl_loeo.py --stage report --set run_name=copl_loeo_adapt

tuned_from은 다른 실행 폴더의 folds/<name>_tune.json을 적용한다(튜닝 5~6시간을 다시 쓰지 않기 위해). 명령줄에서 기본값과 다르게 준 필드는 튜닝값으로 덮지 않고 유지한다. adapt는 adapt_sweep_norms × adapt_sweep_temps × adapt_sweep_evidence 격자를 돌고 설정마다 w_u를 저장한다. 폴드 json만 있는 run이면 report는 report/variants.md를 쓴다.

3.4 결과 공유

git add outputs
git commit -m "Add copl_loeo <stage> run"
git push origin claude_session

outputs/copl_loeo*/는 추적 대상이고 .pt만 제외된다. run_name은 copl_loeo로 시작해야 한다.

4. 자주 바꿀 설정

필드기본의미
channels5채널 (T-IV와 동일)로드할 채널
graph_channels, rm_channels() = channels인코더가 보는 채널 / 보상 모형이 보는 채널. 분리 검정용
encoderaeae, vae, pca, kernel_pca, dtw, scatter, isobank, raw_rbf
graph_rule, knn_k, cross_mintopk, 30, 0희소화 규칙. cross_forced는 이웃 중 최소 cross_min개를 다른 사용자에서
item_item_weight0.5GCF의 λ_ii
rm_bayesnoneensemble / mc_dropout이면 입자 지표(epistemic 등)와 신뢰 구간이 추가됨
pooled_ft_epochs, pooled_ft_lr, pooled_ctx_weight3, 1e-4, 1Pooled-CNN을 (t, 오프셋)마다 population+context로 fine-tune
adapt_evidence, adapt_user_softmax_tempnone, 1.15투표 점수의 t-의존 규칙(none = 원 CoPL, unit = 표준화, sqrt = 표준화 × √t)과 softmax 온도
adapt_degree_norm, adapt_norm_by, adapt_shrink0, items, 0사용자 점수에 ((d̄+κ)/(d_u+κ))^α를 곱한다. d_u = 아이템 수(items) 또는 도달한 표의 양(mass), κ = adapt_shrink × d̄. α=0 = 원 합(큰 사용자로 쏠림, 03의 E5), α=1·κ=0 = 평균 일치도(작은 사용자로 쏠림, E6), κ>0 = 수축(E7)
adapt_sweep_norms, adapt_sweep_norm_by, adapt_sweep_shrinks, adapt_sweep_temps, adapt_sweep_evidence(0,0.5,1), ("items",), (0,), (0.25,…,4), ("none",)adapt 스테이지 격자. α=0 행은 by·κ와 무관하므로 한 번만 돈다
tune_space, tune_trials, tune_inner_folds, tune_budgets9개 축, 40, 3, (0,5,10,20)튜닝 탐색 공간과 예산. 축: gcf_emb_dim, item_item_weight, knn_k, 온도, evidence, degree_norm, neg_weight, gcf_lr, rm_lr
use_tuned, tuned_fromFalse, ""폴드별 튜닝 결과 적용 / 다른 run 폴더의 튜닝 결과 적용
seeds(42,)인코더·GCF·RM·baseline 모두 시드별 재학습
folds()디버그용 held-out 부분집합, 예: --set folds="('강신길',)"

5. 폴드 json 구조

name, n, n_pos, budgets_cfg, encoder, graph_rule, knn_k, graph_channels, rm_channels
copl[t]        시드 평균 지표 (mlpd, auroc, brier, ece, w_entropy, …; rm_bayes면 epi_mean, reliable_frac 등)
pooled[t], indep[t], knn_vote[t]
lpd[method][t] holdout 에피소드별 log predictive density (paired 비교용)
per_seed["copl/42"][t]
w_u[t]         population 사용자별 적응 가중치 평균 (오프셋·시드 평균)
graph[seed]    n_edges, rho_cross, mean_degree, n_components, n_isolated_users
enc_meta[seed], fit_stats, info{n_ctx, n_hold, budgets, offsets}, population_users, cfg_used, seconds

T-IV 폴드 json과 같은 키 규약이라 reward/fully_bayesian/loeo/report.py의 집계 함수가 그대로 동작한다. 가명 E1~E10 매핑은 05 문서(fully_bayesian 쪽)와 같다.

6. 스모크 테스트

python run_copl_loeo.py --stage main --data synthetic --fast --set run_name=copl_smoke
python run_copl_loeo.py --stage report --data synthetic --fast --set run_name=copl_smoke

합성 데이터 5명, 에폭 5로 모든 스테이지가 끝까지 도는지만 확인한다. 성능은 의미 없다.

알려진 비용 요인. DTW 인코더는 \(O(N^2T^2)\)라 실데이터 2600창에서는 오래 걸린다. enc_list에서 빼 두었다. tune은 가장 비싸므로 먼저 tune_trials=10으로 한 폴드만(folds=('강신길',)) 돌려 시간을 재고 전체를 계획하는 편이 좋다.
