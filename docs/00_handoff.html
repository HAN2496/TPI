4. 프로젝트 A: T-IV 논문 (계층 완전 베이지안 선호 모형)

4.1 상태

원고 docs/fully_bayesian/my_papers/main.tex는 수치가 전부 채워진 완성 초안이다(IEEEtran journal, T-IV = IEEE Transactions on Intelligent Vehicles 목표). 남은 것은 사용자가 줘야 하는 메타데이터, 로컬 LaTeX 빌드와 수식 넘침 정리(사용자가 로컬 LLM으로 하기로 했고 프롬프트를 줬다), 수렴 trace 그림, 부록 A(조건부 MI) 실행 또는 삭제, framework 그림의 벡터 정식화다. 실험은 더 돌릴 것이 없다.

4.2 방법 요약

평가자 \(u\)의 로지스틱 계수 \(\boldsymbol\theta_u\)에 population 정규 사전분포를 두고 NIW와 그룹 spike-and-slab까지 전부 Gibbs로 적분한다.

\[ y_{ui}\sim\mathrm{Bern}\big(\sigma(\boldsymbol\theta_u^\top\mathbf z_{ui})\big),\quad \boldsymbol\theta_u=\boldsymbol\gamma\odot\tilde{\boldsymbol\theta}_u,\quad \tilde{\boldsymbol\theta}_u\sim\mathcal N(\boldsymbol\mu,\boldsymbol\Sigma),\quad (\boldsymbol\mu,\boldsymbol\Sigma)\sim\mathrm{NIW}(\mathbf 0,1,d+2,\lambda_0\mathbf I),\quad \gamma_g\sim\mathrm{Bern}(\pi),\ \pi\sim\mathrm{Beta}(1,1) \]

Pólya–Gamma 증강으로 계수 갱신, NIW 닫힌 갱신, 그룹 포함 지표는 증강 우도의 log Bayes factor로 Bernoulli 갱신. burn-in 500, 보존 1500 sweep. 새 평가자는 particle마다 \(\tilde{\boldsymbol\theta}^{(m)}_\star\sim\mathcal N(\boldsymbol\mu^{(m)},\boldsymbol\Sigma^{(m)})\)로 cold start, 문맥 라벨로 PG sweep 8회 갱신. 예측은 particle 평균. 불확실성은 \(\hat p(1-\hat p)=\mathbb E_m[p^{(m)}(1-p^{(m)})]+\mathrm{Var}_m(p^{(m)})\)로 aleatoric/epistemic 분해, 평가자 단위 신뢰 구간은 particle × bootstrap AUROC의 2.5/97.5 백분위(\(w_{\max}=0.3\)). 피처는 ISO 기반 통계 bank를 상관 0.95로 가지치기해 40개 + 절편. 선택은 PIP와 projection-predictive forward search + 폴드 내 재적합 + one-SE 규칙, 센서는 31개 부분집합 전수 재적합. 역할 분류는 \(q_j=\mathbb E_m[\Phi(|\mu_j|/\sqrt{\Sigma_{jj}})]\ge0.9\)이면 common.

5.2 방법 요약과 수정 이력

CoPL(Choi et al., EMNLP 2025, arXiv:2503.01658): 사용자–아이템 이분 그래프(good 간선 \(A_+\), bad 간선 \(A_-\)) + 아이템–아이템 kNN 그래프 \(A_{ii}\) 위 LightGCN식 전파로 \(e_u, e_i\); CNN 보상 모형 \(r(x;e)\); 새 사용자는 문맥 라벨로 population 사용자 가중치 \(w_u\)를 만들어 \(\hat e_\star=\sum_u w_ue_u\). 핵심 관찰: 에피소드는 한 사람 것이라 그래프가 별들의 합이고 사용자 간 다리는 \(A_{ii}\)뿐.

학습 쪽 수정(E2~E4): 검증 AUROC 선택 → 검증 BCE 선택, 온도 보정, 앙상블 3, mixture-consistent training(학습 행의 절반을 \((1-\lambda)e_u+\lambda\sum_{u'}\pi_{u'}e_{u'}\), \(\pi\sim\mathrm{Dir}(1)\), \(\lambda\sim U(0,1)\)로 대체). 인코더는 Gabor scattering(E1: held-out 투표 AUROC 0.719, AE 0.546, VAE 0.542).

적응 쪽 수정(E5~E8): 원 투표 \(c_u=\sum_{i\in I_u}s_iv_i\)는 \(\mathbb E[c_u]\propto n_u\)라 라벨이 가장 많은 사용자로 쏠린다(E5: 10명 전부). degree 정규화 \(c_u(\bar n/n_u)^\alpha\)는 작은 사용자로 쏠리고(E6), 수축 \(c_u\frac{\bar d+\kappa}{d_u+\kappa}\)는 36 설정 중 10폴드 통과 없음(E7). 대체 규칙(E8, 채택):

\[ \ell_u=\sum_{i\le t}\Big[y_i\log\sigma(r(x_i;e_u))+(1-y_i)\log\big(1-\sigma(r(x_i;e_u))\big)\Big],\qquad w_u=\frac{e^{\ell_u/\tau}}{\sum_{u'}e^{\ell_{u'}/\tau}} \]

\(\tau=1\)이 균등 사전분포 아래의 정확한 posterior, \(\tau>1\)이 tempered posterior. 그래프 불필요, degree 편향 없음, 증거가 \(t\)에 비례해 쌓임. \(\tau\)와 표준화 여부는 내부 LOEO로 선택(E9: 8폴드 \(\tau=1\), 2폴드 2).

6. 두 논문의 분리 규칙

  • CoPL 원고의 베이스라인은 Pooled-CNN, Indep-CNN, kNN vote만. 계층 베이지안 모형과 비교하지 않고 "우리의 다른 논문"을 언급하지 않는다.
  • 같은 데이터·프로토콜이지만 문장을 공유하지 않는다. 가명 매핑은 같다.
  • CoPL 원고는 피처 bank를 쓰지 않고(파형 입력), 불확실성을 주장하지 않으며, 센서 결론은 IV 버전에서 뺀다.
  • T-IV 원고는 CoPL을 언급하지 않는다.

8. 알려진 함정과 수정 이력

  • --fast는 기본값인 필드에만 FAST 프리셋을 적용한다(명시한 --set을 덮지 않음). 두 드라이버 공통.
  • read-only 스테이지(report/select/sensors/ablate/sweep/channels/adapt/tune)와 use_tuned(tuned_from 없을 때)는 --timestamp 생략 시 같은 run_name의 최신 폴더를 쓴다. 폴드 json이 없는 빈 폴더는 건너뛴다.
  • _tuned는 명령줄에서 기본값과 다르게 준 필드를 튜닝값으로 덮지 않는다(명령줄이 probe). FAST 모드에서는 FAST가 바꾼 필드도 "명령줄"로 간주된다.
  • CoPL 데이터셋의 검증 분할: 라벨 2개 미만이거나 클래스당 2개 미만인 사용자는 학습 전용(계층 분할이 실패하던 버그 수정).
  • kNN vote 베이스라인은 문맥을 쓰지 않는다(설계상). 모든 예산에서 같은 값.
  • cross_forced 그래프 규칙은 중복 간선을 coalesce로 합산(수정됨). dense 규칙은 느리고 기본이 아니다.
  • 인코더 내재 지표는 사용자별 macro로 계산해야 한다(한 덩어리로 섞으면 base rate 차이에 왜곡).
  • hamiltorch는 선택 의존성(없어도 import 됨).
  • matplotlib mathtext: \big, \underbrace, \le, \textstyle 불가. 합 기호는 \Sigma_u로 쓰면 줄 높이가 안 깨진다.
  • 클라우드 컨테이너의 네트워크: PyPI·npm은 직접, GitHub은 세션 프록시(허용된 저장소만), CTAN·raw.githubusercontent의 임의 저장소는 403. 외부 파일은 사용자에게 받거나 저장소에 넣는다.
  • T-IV 그림 4장의 생성 코드는 원래 세션에서 inline으로 실행되어 저장소에 없었다. 2026-10-08 세션 기록에서 복원해 make_results.py로 저장했고 PNG가 동일함을 확인했다.
  • outputs/의 폴더 삭제는 git rm -r로. 실패했거나 대체된 실행(copl_loeo/20261004_*)은 이미 지웠다.
  • E5의 적응 가중치 붕괴를 분석할 때 "폴드별 최선 설정"은 테스트 폴드로 고른 것이므로 상한으로만 쓰고 결과로 쓰지 않는다.
